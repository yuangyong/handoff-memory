# 路线图

Handoff Memory 当前处于 Alpha 阶段。路线图表达唯一维护者当前考虑的优先级和完成条件，不承诺固定日期；实际顺序会根据安全问题、兼容性变化、维护成本和用户反馈调整。

## 近期：可重复发布

- 建立由正式版本标签触发的 PyPI 单一分发流程。
- 使用 PyPI Trusted Publishing 和受保护 Environment，避免长期发布 Token。
- 保证发布质量门和 PyPI 上传使用同一份构建产物。
- 保持发布 Job 最小权限，并让外部 Action 固定到完整提交 SHA。
- 为 Markdown 外部链接建立定期检查，及时发现厂商文档迁移。
- 持续验证 Windows 并发保存锁在公开 CI 中的长期稳定性。
- 增加覆盖率报告、格式基线、静态类型与复杂度质量门。
- 提供可独立验证的安装后冒烟测试和发布记录。

版本决策、质量门、PyPI、Yank 与事件处理流程见[发布手册](RELEASING.md)。

## 中期：维护性与兼容性

- 在不破坏 CLI/JSON 契约的前提下，逐步拆分 `core.py` 和 CLI 主调度中的高复杂度职责。
- 定期核验 12 个 AI 客户端的官方 Skill/规则目录和触发语义。
- 为公共 JSON schema、快照格式和版本迁移补充更集中的兼容性文档。
- 扩充 Windows、macOS、Linux 上的并发、路径、编码和文件系统边界测试。

## 后续候选方向

- 可选的快照索引与搜索，但不改变 Markdown 是事实载体的原则。
- 可选的来源追溯元数据，但不依赖厂商私有会话 ID。
- 更完整的英文文档和版本化文档站。
- 面向团队的策略示例，例如交接内容最小化、保留周期和 CI 隐私检查。

## 明确不在路线图中的事项

- GitHub Release 发行附件、独立可执行文件、WinGet、Homebrew、Scoop 或远程安装脚本。
- 默认联网、遥测或上传交接内容。
- 自动记录每轮聊天或在任务完成、提交代码、会话退出时自动保存。
- 执行交接中记录的命令。
- 强制依赖某个模型、AI 客户端、云账户或向量数据库。

功能建议请使用 GitHub Issue 模板，说明用户问题、预期行为、安全与兼容性影响，以及为什么现有命令无法满足需求。建议会作为维护者决策的输入，不构成路线图或实现承诺。
