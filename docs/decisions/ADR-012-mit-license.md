# ADR-012：首次公开发布采用 MIT License

## 状态

已接受

## 日期

2026-07-13

## 背景

Handoff Memory 即将从私有仓库转为公开仓库，需要在首次公开发布前确定清晰、易识别且与项目目标一致的开源许可证。项目是零运行期第三方依赖的 Python CLI，希望个人、团队和不同 AI 工具生态能够低门槛地使用、修改、集成和再分发。

仓库此前准备使用 Apache License 2.0，但尚未完成首次公开发布，也没有需要维持原许可证预期的外部发布消费者。维护者确认当前提交作者邮箱和 `yuangyong` 身份用于公开开源活动。

## 决策

- 项目采用 MIT License。
- 根目录 `LICENSE` 使用标准 MIT 许可证正文，版权所有者为 `yuangyong`，年份为 2026。
- Python 包元数据使用 SPDX 表达式 `MIT`。
- 接受的贡献默认按仓库 MIT License 分发；贡献者必须有权提供相关内容。
- 第三方代码、素材和文档继续遵守其原始许可证与归属要求；MIT License 不会覆盖第三方已有义务。

## 备选方案

### Apache License 2.0

未选择。它提供更明确的专利授权和专利诉讼终止条款，但正文和再分发义务更长。当前项目优先考虑简单、广泛识别和低集成门槛。

### GPLv3

未选择。强 copyleft 能要求衍生作品保持相同许可，但会限制部分商业或闭源集成场景，不符合跨工具广泛采用的当前目标。

### 暂不提供开源许可证

拒绝。公开可见不等于允许使用、修改和再分发；缺少许可证会给用户和贡献者带来不必要的不确定性。

## 影响

- 用户可以在保留版权与许可声明的条件下使用、复制、修改、合并、发布、分发、再许可和销售软件副本。
- 软件按“原样”提供，不附带保证；具体条款以根目录 `LICENSE` 为准。
- 相比 Apache-2.0，MIT License 没有同等详细的显式专利授权条款，也没有 `NOTICE` 机制。
- README、包元数据、贡献说明、发布清单和发行包必须保持 `MIT` 表述一致。
- 如果未来改变许可证，应新增 ADR 说明适用版本、已有贡献权利和迁移边界，不删除本记录。
