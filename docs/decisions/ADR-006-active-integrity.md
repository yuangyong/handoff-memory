# ADR-006：校验活动交接与最后保存正文的一致性

## 状态

已接受

## 日期

2026-07-12

## 背景

`ACTIVE.md` 是当前任务的唯一活动入口，允许用户在保存后继续编辑；历史快照则只增不改。旧版 `resume` 读取当前 `ACTIVE.md`，同时展示 `config.json` 中的上次保存时间和仓库状态，但无法判断正文是否也来自同一次保存。这可能让新会话误把未归档编辑当成最后快照的精确内容。

项目需要保持本地文件、跨 AI 客户端和无厂商私有会话依赖的核心设计，因此不能依赖某个客户端才有的会话 ID。

## 决策

- `save` 对规范化后的交接正文计算 SHA-256，并写入 `config.json` 和历史快照 YAML 元数据。
- `resume` 继续读取当前 `ACTIVE.md`，同时比较其摘要与最后保存摘要。
- Markdown 和 JSON 输出均报告正文一致、已变化或旧配置暂时无法核验。
- 摘要字段作为 schema v1 的向后兼容可选扩展；旧项目在下一次保存前仍可恢复。
- 不在 `ACTIVE.md` 中记录其自身哈希，避免正文写入导致摘要自指失效。
- 恢复流程保持只读，不会为了补写摘要而迁移旧配置或创建快照。

## 备选方案

### 恢复时始终读取最后快照

拒绝。它会忽略用户在 `ACTIVE.md` 中有意保留的最新任务进展，破坏活动入口语义。

### 依赖 AI 客户端会话 ID

拒绝作为核心设计。不同客户端的会话标识能力不一致，也不属于项目级任务接续的必要条件。

### 把 `ACTIVE.md` 哈希写入正文

拒绝。写入哈希会改变正文自身，无法形成稳定的自校验值。

## 影响

- 新会话可以立即识别交接正文是否包含保存后的未归档编辑。
- 旧配置保持可读，只会显示一次“暂时无法核验”提示，下一次保存后自动具备摘要。
- JSON 消费者会看到三个新增字段，但现有字段和 schema 版本不变。
- SHA-256 只用于一致性检测，不代表内容可信；任务事实仍需结合当前代码、版本库和测试核验。
