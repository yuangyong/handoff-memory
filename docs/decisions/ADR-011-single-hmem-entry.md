# ADR-011：公开发布只保留 `hmem` 命令

## 状态

已接受；取代 ADR-008 中的双入口决定

## 日期

2026-07-13

## 背景

开发阶段曾同时安装 `hmem` 与一个完整名称的 console script。双入口会扩大帮助、文档、测试和自动化的公共契约，并在尚未正式发布时提前背负永久兼容成本。当前没有需要迁移的已发布消费者，因此应在首次公开发布前收敛接口。

发行包名、Python 模块名、规则文件名以及 `handoff-memory:start/end` 受管标记属于不同命名空间，不应因 CLI 收敛而改变。

## 决策

- Wheel 只安装 `hmem = handoff_memory.cli:main` 一个 console script。
- 帮助、版本、错误提示和所有命令示例始终使用 `hmem`，不根据启动器文件名动态变化。
- `python -m handoff_memory` 与直接调用 `main()` 继续使用相同的 `hmem` 品牌和命令契约。
- Skill 和客户端规则只调用 `hmem`；命令不存在时提示安装，不尝试其他入口。
- Python 发行包继续命名为 `handoff-memory`，模块继续命名为 `handoff_memory`。
- 规则路径、锁目录和受管标记保持原名，以避免无关的数据格式迁移。

## 备选方案

### 永久保留双入口

拒绝。尚未公开发布时不存在足以抵消长期维护成本的兼容收益。

### 先弃用、以后移除

拒绝。弃用期适用于已有真实消费者的公共接口；对开发阶段入口增加弃用流程只会制造无效复杂度。

### 同时重命名发行包和内部标记

拒绝。安装名称、终端命令和数据协议是独立接口，同时迁移会扩大风险且没有用户价值。

## 影响

- 用户安装 `handoff-memory` 发行包后只使用 `hmem`。
- 发布包、文档、Skill 和 CI 只有一套命令契约。
- 若有人使用过开发阶段旧入口，迁移方式是把命令前缀直接替换为 `hmem`；参数和行为不变。
- ADR-008 保留为历史决策记录，但其双入口结论不再生效。
