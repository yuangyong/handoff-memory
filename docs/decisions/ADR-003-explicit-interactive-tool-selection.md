# ADR-003：使用显式零依赖列表选择 AI 工具

## 状态

已接受

## 日期

2026-07-12

## 背景

`init --integrate TARGET` 适合脚本，但用户必须先记住目标短名称，而且一次只能选择一个。若所有 `init` 默认弹出交互菜单，则 CI、管道和无人值守安装可能挂起。引入第三方终端 UI 库又会破坏项目的零运行期依赖原则。

## 决策

- 保留 `--integrate TARGET` 作为稳定的非交互接口。
- 新增 `--select-tools`，仅在用户显式指定时显示编号列表。
- 列表支持逗号分隔多选、`all` 全选、直接回车跳过，并对非法输入给出中文提示后重试。
- 客户端清单仅收录具有公开、稳定项目规则或项目级 Skill 目录约定的工具；每个适配器写入官方目录，并只维护带标记的区块。
- 项目级 Skill 的原生目录策略由 ADR-004 规定；规则生成策略由 ADR-005 规定。
- 新增 `help [COMMAND]`，同时保留 argparse 标准 `-h/--help`。

## 备选方案

### 每次初始化自动弹出菜单

会改变已有命令的可观察行为，并可能阻塞脚本，拒绝。

### 引入 questionary、Inquirer 等终端 UI 依赖

能提供方向键和复选框，但为了一次低频初始化增加运行期依赖不划算，拒绝。

### 只保留单个 `--integrate`

对初次使用者不友好，也不便于多客户端项目，拒绝。

## 后果

- 交互体验是清晰的终端列表而非图形下拉框，但跨 Windows、macOS、Linux 且无需额外依赖。
- 旧脚本保持兼容，交互行为可测试、可通过标准输入驱动。
- 新客户端只有在确认官方规则和/或项目级 Skill 目录约定后才加入清单。
