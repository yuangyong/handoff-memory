# ADR-009：可靠保存与完整工作区漂移

## 状态

已接受

## 日期

2026-07-12

## 背景

仅比较分支、提交和工作区是否为 dirty，无法识别 dirty→dirty 期间具体文件集合或状态的变化。多个 AI 客户端也可能同时保存同一项目；只依赖“先检查文件名、再原子替换”会留下覆盖同名快照的竞态。

## 决策

- Git 与 SVN 对截断前的完整规范化状态、变更路径内容和相关元数据计算 SHA-256，并记录变更总数；Git 还包含暂存区对象信息。
- `resume` 比较保存与当前指纹；旧配置没有指纹时明确报告无法核验，不把未知解释为稳定。
- 指纹忽略 `config.json`、历史快照、临时文件和锁等 Handoff Memory 内部记账，但保留 `ACTIVE.md`。
- 同一项目的保存通过系统临时目录中的项目级锁串行化，不把锁文件写入目标仓库。
- 锁使用 Windows `msvcrt` 或 POSIX `flock` 的操作系统文件锁并设置等待超时；进程退出或崩溃时由操作系统自动释放，不需要存在竞态的陈旧锁接管。不同项目使用不同锁，可并行保存。
- 快照先完整写入同目录临时文件，再通过排他硬链接一次性发布；目标存在时拒绝覆盖，也不暴露零字节占位窗口。
- 历史检查负责暴露损坏快照和可能由中断保存留下的异常快照，不自动删除或修复历史。

## 备选方案

### 只比较 dirty 布尔值

拒绝。它无法回答保存后具体工作集是否发生变化。

### 把完整 Git/SVN 状态无限写入恢复上下文

拒绝。展示仍限制为最多 200 条；完整状态和变更内容只在本地流式计算摘要，不写入恢复上下文。

### 在项目目录创建锁文件

拒绝。锁自身会污染工作区状态并制造伪漂移。

### 自动删除孤立或损坏快照

拒绝。历史是审计资料，诊断可以自动完成，删除必须由用户明确决定。

## 影响

- dirty→dirty 的具体变化可以被可靠识别。
- 旧项目保持可读，在下一次保存后获得完整指纹。
- 同项目并发保存被串行化，快照不会被静默覆盖。
- 进程崩溃仍可能留下可诊断的部分状态，但不会触发自动历史删除。
