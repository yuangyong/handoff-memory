# ADR-010：机器可读操作与只读历史

## 状态

已接受

## 日期

2026-07-12

## 背景

`resume` 已提供稳定 JSON，但 `save` 和 `check` 仍只有面向人的文本，Skill 或自动化只能解析中文输出。历史快照虽然存在于磁盘，却没有安全的只读枚举和查看入口；用户在 `ACTIVE.md` 被误写时只能手工寻找文件。

## 决策

- `save` 与 `check` 增加 `--format json`，现有文本输出和退出码保持兼容。
- 所有 JSON 成功输出顶层保留 `schema_version` 与 `ok: true`，新增字段只做向后兼容扩展。
- `check --strict` 把质量警告提升为失败，默认检查仍保持非阻断。
- `check --privacy` 启用可选个人信息提示；默认安全行为只阻断高置信度密钥。
- 增加只读 `history` 与 `show`：前者枚举快照摘要，后者按安全 basename 或 `latest` 查看精确快照；`latest` 优先使用配置记录的最后完整保存。
- 历史命令拒绝路径穿越、符号链接、损坏元数据、超限内容和疑似密钥，不修改 `ACTIVE.md`、配置或快照；即使 `ACTIVE.md` 缺失或配置损坏，也能降级读取历史用于救援。
- 损坏或疑似中断保存留下的快照只报告诊断，不自动删除、恢复或覆盖。

## 备选方案

### 让 Skill 解析中文输出

拒绝。文本措辞是人机界面，不应成为跨客户端机器契约。

### 默认把所有质量提示变成错误

拒绝。不同任务类型的证据表达不同，默认严格会破坏现有有效交接；CI 可显式使用 `--strict`。

### 提供自动 restore 命令

暂不采用。恢复历史会写入活动状态，风险高于只读查看；用户可审查后明确更新并保存。

## 影响

- AI Skill 和 CI 可以使用稳定 JSON，不再依赖中文文本解析。
- 用户可以安全审计历史，但历史不会自动改变当前任务。
- 新子命令和参数均为增量接口，旧脚本继续工作。
