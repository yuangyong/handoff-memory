# ADR-004：具名客户端生成原生项目级 Skill

## 状态

已接受

## 日期

2026-07-12

## 背景

Handoff Memory 的规则文件只适合提供轻量提醒，完整的保存、恢复、安全检查和版本库核验流程位于 `session-handoff` Skill。如果某个客户端接入只生成规则，没有把 Skill 放入它能自动发现的项目目录，AI 仍需要靠规则重新解释流程，接入是不完整的。

当前 11 个具名客户端都已公开项目级 Agent Skills 目录，但目录名称并不统一。

## 决策

- 每个具名客户端生成原生项目级 `session-handoff/SKILL.md`；具有独立规则文件的客户端同时生成规则。
- 使用 `PROJECT_SKILL_PATHS` 作为目标到原生目录的唯一映射；新增目标必须同时增加 Skill 路径和文件系统测试。
- 所有目录写入同一份 `SKILL_TEMPLATE`，确保跨客户端流程一致。
- 继续保留 `generic` 作为仅规则基线，保留 `skill` 作为 `.agents/skills` 可移植副本入口。
- `AGENTS.md` 仍是显式可选的轻量路由，不替代 Skill，也不因生成 Skill 而默认创建。

## 备选方案

### 所有客户端统一写入 `.agents/skills`

部分客户端支持该开放目录，但原生目录的发现兼容性更明确，也便于从文件树判断接入了哪个客户端，因此拒绝作为唯一输出。

### 只生成规则并让规则描述完整流程

会把多步骤流程常驻上下文，且不同规则模板容易漂移，违背按需加载 Skill 的设计，拒绝。

### 只为 Codex 和 OpenCode 生成 Skill

其他已支持 Agent Skills 的客户端会得到不完整接入，拒绝。

## 后果

- 单个具名目标通常会新增两个文件：客户端规则和原生项目级 Skill。
- `all` 会在多个目录保存内容相同的 Skill，这是为了确定性发现而接受的少量文件重复。
- Skill 模板更新会由所有客户端共享，避免保存与恢复行为分叉。
