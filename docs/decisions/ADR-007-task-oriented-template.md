# ADR-007：使用任务导向的通用交接模板

## 状态

已接受

## 日期

2026-07-12

## 背景

Handoff Memory 最初主要服务 AI 编程客户端，`ACTIVE.md` 使用“修改文件”和“验证结果”等偏编码的章节。用户也会在同一类 AI 工具中持续处理写作、研究、规划和方案讨论；这些任务同样需要跨会话接续，但不一定有源代码、测试命令或版本库。

另一方面，没有持续目标的纯闲聊不需要任务交接。保存聊天全文既降低上下文质量，也增加个人信息进入项目文件的风险。

## 决策

- 产品定位保持为跨 AI 工具的任务接续器，不扩展为逐轮聊天记录器。
- 新模板继续使用七个章节，但采用任务通用名称：当前目标、已完成、关键上下文与决策、产物与变更、验证与依据、阻塞与风险、下一步。
- 编码任务把文件和测试写入“产物与变更”“验证与依据”；非编码任务可记录草稿、链接、数据、来源或人工确认。
- 纯闲聊且没有持续目标时通常不保存。用户明确要求保存时，只提炼未来要继续的话题和必要上下文，不复制聊天全文。
- 旧标题“关键决策”“修改文件”“验证结果”作为兼容别名继续通过校验，不强制迁移已有项目和快照。
- 质量检查只对缺少验证依据或无序下一步给出非阻断提示，避免对不同任务类型施加过窄格式。

## 备选方案

### 为编码和普通任务提供两套模板

暂不采用。双模板需要初始化选项、迁移策略和两套校验契约，增加选择成本；七个核心信息维度本身可以跨任务复用。

### 保存所有普通聊天

拒绝。它偏离任务接续目的，会产生大量低价值上下文和隐私风险。

### 保留代码专用标题，让非编码任务填写“无”

拒绝。大量“无修改文件”“无测试”会降低信息密度，也会让用户误以为产品只适用于代码。

## 影响

- 新建项目获得更通用、可执行的任务交接提示。
- 旧项目无需修改即可继续保存和恢复。
- Git/SVN 状态仍会在可用时自动采集，但不再被视为所有任务的唯一证据。
- Skill 需要按任务类型选择核验方式，并避免把普通聊天全文写入交接。
