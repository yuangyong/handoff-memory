# ADR-008：使用 `hmem` 作为主命令并兼容完整命令

## 状态

已被 ADR-011 取代

## 日期

2026-07-12

## 背景

发行包和产品名称 `handoff-memory` 能准确表达用途，但作为高频 CLI 前缀过长，降低了手工操作、提示词和文档示例的可读性。命令已经出现在用户脚本、项目级 Skill 和 CI 中，因此直接重命名或弃用会破坏现有接入。

命令名称只属于交互入口，不应改变发行包名、Python 模块名、`.ai-memory` 数据协议、规则文件名或 `handoff-memory:start/end` 受管标记。

## 决策

- 使用 `hmem` 作为推荐的主命令和新文档、Skill、规则中的默认示例。
- 保留 `handoff-memory` 作为永久兼容入口，不设置移除计划，也不显示弃用警告。
- 两个入口调用同一个 CLI 主函数，参数、业务行为和退出码必须一致。
- 帮助、版本和示例使用用户实际调用的入口名，避免运行 `hmem` 时仍展示完整命令。
- 直接调用 `main([...])`、通过 `python -m handoff_memory` 启动或无法识别启动器时，确定性使用 `hmem`。
- Python 发行包继续命名为 `handoff-memory`，模块继续命名为 `handoff_memory`。
- CI 必须从构建后的 Wheel 核验两个 `console_scripts`，并分别执行两个入口的冒烟检查。

## 备选方案

### 继续只使用 `handoff-memory`

优点是无需增加入口；缺点是高频命令冗长，无法解决本次可用性问题。

### 使用 `hm`

更短，但含义过于通用，品牌辨识度和命令冲突控制都较弱。

### 使用 `handoff`

语义直接，但长度改善有限，并容易与其他同名工具混淆。

### 删除完整命令

只能保留一个入口，但会无必要地破坏已有脚本、Skill 和 CI，不符合公共 CLI 的向后兼容原则。

## 影响

- 新用户获得更短、更易识别的日常命令。
- 已有自动化无需迁移，可以长期继续使用 `handoff-memory`。
- 发行物会安装两个很小的控制台启动器，但运行逻辑没有重复实现。
- 文档维护时必须区分命令语境与包名、路径、标记语境，不能机械替换所有 `handoff-memory` 字符串。
- 发布门禁需要持续防止任一入口遗漏或行为漂移。
