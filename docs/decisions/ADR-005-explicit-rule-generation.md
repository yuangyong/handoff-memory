# ADR-005：客户端规则改为显式生成

## 状态

已接受

## 日期

2026-07-12

## 背景

Handoff Memory 的核心能力位于 `session-handoff` Skill。0.9.0 及更早版本中，部分具名客户端在接入时默认同时生成 Skill 和规则，而 Codex、OpenCode 的根目录 `AGENTS.md` 又需要额外参数。这造成相同的“接入客户端”操作在不同工具上具有不同副作用，也让 `--with-agents-rule` 看起来像通用规则开关，实际却只控制两个客户端。

规则通常会进入客户端常驻或高优先级上下文；用户只想安装按需加载的 Skill 时，不应被隐式加入自动提醒。

## 决策

- 所有具名客户端默认只生成其原生项目级 `session-handoff` Skill。
- 新增统一选项 `--with-rules`，显式生成所选客户端的原生规则。
- Codex 和 OpenCode 没有独立规则文件时，由 `--with-rules` 创建或幂等更新根目录 `AGENTS.md` 轻量路由。
- 移除语义过窄的 `--with-agents-rule`，不保留兼容别名；旧脚本必须替换为 `--with-rules`。
- `all` 只表示全部具名客户端；`generic` 和 `skill` 辅助目标必须单独指定。
- 已存在的规则文件不会因省略 `--with-rules` 而自动删除，避免破坏用户在受管区块外添加的内容。

## 备选方案

### 保持不同客户端的历史默认行为

会继续产生“同一命令、不同副作用”，并无法解释为什么某些规则需要参数、某些规则不需要，因此拒绝。

### 保留 `--with-agents-rule` 作为兼容别名

两个名称同时存在会延续“AGENTS.md 专用开关还是全部规则开关”的歧义。项目仍处于 Alpha 阶段，选择一次性统一接口，并在 CHANGELOG 与使用指南中提供直接替换方式。

### 默认生成全部规则，增加 `--skills-only`

默认副作用仍然偏重，且新用户必须先知道如何关闭规则，不符合 Skill 为核心、规则为可选提醒的设计，因此拒绝。

## 后果

- `handoff-memory init . --select-tools` 不再隐式生成任何客户端规则。
- 需要规则的用户必须增加 `--with-rules`。
- 从旧版本升级后重新运行不带参数的 `integrate` 不会删除已有规则；需要移除时应人工确认规则文件没有用户内容后再删除。
- CLI、文档、测试和 CI 统一使用一个规则开关，后续新增客户端不再设计专用参数。
