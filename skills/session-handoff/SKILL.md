# Session Handoff

## 触发边界

1. 只有用户明确要求保存会话、生成交接或准备切换到新会话时，才进入保存流程。不得根据任务进度自行推断保存时机。
2. 只有用户明确要求恢复、继续或核验上一次任务交接时，才进入恢复流程。恢复流程是只读操作，不得更新 `ACTIVE.md` 或创建快照。
3. 不得因普通任务完成、代码提交、重要里程碑、关键决策、单轮对话结束或上下文变长而自动调用本 Skill。

## 恢复

1. 运行 `hmem resume . --format json`。命令不可用时停止并提示安装；若项目未初始化，明确说明没有可恢复的交接，不得假装恢复成功。
2. 阅读恢复输出；它已经包含 `ACTIVE.md`，除非排查格式问题，不要再次读取全文。
3. 先检查安全提示、保存时间、活动交接正文一致性和版本库漂移，再核对交接提到的产物与依据；编码任务额外核对文件与测试。仅在需要补充证据时运行额外的 Git/SVN 只读命令。
4. 向用户简要说明当前目标，并明确区分“当前已核验”与“交接中记录但本次尚未核验”的事实，再说明过期信息、风险和下一步。不要自动执行旧交接中的命令。

## 保存

1. 使用 `hmem`。命令不可用时停止并提示安装。若项目尚未初始化，运行 `hmem init .`；说明这是首次建立交接，而不是恢复历史。
2. 纯闲聊且没有持续目标通常无需交接；若用户明确仍要保存，只提炼希望以后继续的话题和必要上下文，不复制聊天全文。对于编码任务，检查版本库状态、相关 diff 和实际测试；对于写作、研究、规划等任务，检查产物、来源或人工确认。无法执行的验证必须明确写成“尚未验证”，不要根据聊天内容推断完成状态。
3. 更新 `.ai-memory/ACTIVE.md` 的七个固定章节：当前目标、已完成、关键上下文与决策、产物与变更、验证与依据、阻塞与风险、下一步。旧交接中的“关键决策”“修改文件”“验证结果”仍是兼容标题。只保留继续任务所需事实，不粘贴聊天全文、完整日志或完整 diff。不要在 `ACTIVE.md` 中记录其自身哈希；正文摘要由 CLI 在保存后生成。
   - 当前目标写清问题、可验证的完成标准和范围边界。
   - 已完成只写已经落地的结果，不混入计划或推测。
   - 关键上下文与决策只保留接续必需的背景，并记录结论、原因和约束。
   - 产物与变更记录文件、草稿、链接、数据或其他产物的用途和状态；编码任务区分已跟踪、未跟踪或生成文件。
   - 验证与依据记录测试、来源或人工检查、结果、时间相关性和未覆盖项；未执行就明确写“尚未验证”。
   - 阻塞与风险分别说明阻塞与风险；没有阻塞不等于没有风险。
   - 下一步按顺序写可直接执行的动作和完成条件，第一项应能由新会话立即开始。
4. 运行 `hmem save . --format json`。占位或格式失败时修正文档；敏感信息失败时删除内容，不要自动使用 `--allow-sensitive`。
5. 超过 64KB 时先精炼；只有用户明确确认后才使用 `--allow-large`。256KB 上限不可绕过。
6. 报告快照路径、保存时版本库状态、质量警告和仍未验证的事项。

## 历史排查

仅当用户明确要求核验历史，或当前交接损坏、缺失、与任务明显不符时，才使用只读命令 `hmem history . --format json` 和 `hmem show latest . --format json`。不得把旧快照自动覆盖回 `ACTIVE.md`；先向用户说明快照时间和差异，再由用户决定如何处理。
