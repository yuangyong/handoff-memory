# Handoff Save

## 触发边界

1. 只有用户明确要求保存会话、生成交接或准备切换到新会话时，才进入本流程。
2. 不得因普通任务完成、代码提交、里程碑、关键决策、单轮对话结束或上下文变长而自动触发保存。

## CLI 可用性检查

1. 先运行 `hmem --version` 检查 CLI。
2. 若 `hmem` 不可用，探测本机是否有 `uv` 或 `pipx`：
   - 若存在 `uv` 或 `pipx`，**停止并向用户展示标准安装命令**（`uv tool install handoff-memory` 或 `pipx install handoff-memory`），**征得用户明确同意后再执行安装并验证 `hmem --version`**；不得静默运行远程安装脚本或强行向系统 Python 安装。
   - 若均不可用或处于离线/受限环境，停止操作并向用户说明安装方法。

## 目录检查与自动初始化

1. 确认当前工作目录属于目标项目（若处于用户主目录 `~` 或盘符/系统根目录，先向用户确认真实项目目录，禁止误初始化）。
2. 检查当前目录 `.ai-memory/` 状态：
   - **完全未初始化**（不存在 `.ai-memory/`）：自动执行 `hmem init .` 仅创建 `.ai-memory/` 目录（不生成项目级客户端规则或 Skill），并告知用户这是首次建立交接。
   - **部分存在或疑似损坏**（存在 `.ai-memory/` 但缺少 `ACTIVE.md` 或 `config.json` 异常）：**禁止**运行 `hmem init --force` 覆盖，先用只读命令 `hmem history . --format json` 排查并向用户报告。

## 保存流程

1. 纯闲聊且没有持续目标通常无需交接；若用户明确仍要保存，只提炼希望以后继续的话题和必要上下文，不复制聊天全文。
2. 保存前按任务类型核验事实：编码任务检查版本库状态、相关 diff 和实际测试；写作、研究或规划任务检查产物、来源或人工确认。无法执行的验证必须明确写成“尚未验证”，不要根据聊天内容推断完成状态。
3. 更新 `.ai-memory/ACTIVE.md` 的七个固定章节：当前目标、已完成、关键上下文与决策、产物与变更、验证与依据、阻塞与风险、下一步。旧交接中的“关键决策”“修改文件”“验证结果”仍是兼容标题。只保留继续任务所需事实，不粘贴聊天全文、完整日志或完整 diff，不要在正文中记录其自身哈希（正文摘要由 CLI 在保存后生成）。
   - 当前目标写清问题、可验证的完成标准和范围边界。
   - 已完成只写已经落地的结果，不混入计划或推测。
   - 关键上下文与决策只保留接续必需的背景，并记录结论、原因和约束。
   - 产物与变更记录文件、草稿、链接、数据或其他产物的用途和状态；编码任务区分已跟踪、未跟踪或生成文件。
   - 验证与依据记录测试、来源或人工检查、结果、时间相关性和未覆盖项；未执行就明确写“尚未验证”。
   - 阻塞与风险分别说明阻塞与风险；没有阻塞不等于没有风险。
   - 下一步按顺序写可直接执行的动作和完成条件，第一项应能由新会话立即开始。
4. 运行 `hmem save . --format json`。占位或格式失败时修正文档；敏感信息失败时删除相关内容，不要自动使用 `--allow-sensitive`。
5. 超过 64KB 时先精炼；只有用户明确确认后才使用 `--allow-large`。256KB 上限不可绕过。
6. 报告快照路径、保存时版本库状态、质量警告和仍未验证的事项；若本次触发了首次自动初始化且项目位于 Git/SVN 中，提醒用户按团队习惯决定是否忽略或提交 `.ai-memory/`。
