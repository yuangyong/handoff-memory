# Handoff Resume

## 触发边界

1. 只有用户明确要求恢复、继续、核验上一次任务交接，或要求排查历史快照时，才进入本流程。
2. 本 Skill **全流程严格只读**：不得更新 `.ai-memory/ACTIVE.md`、不得创建新快照，也不得在未初始化项目上自动运行 `hmem init`。
3. 不得因普通对话开始或任务启动而自动加载或恢复交接。

## CLI 可用性检查

1. 先运行 `hmem --version` 检查 CLI。
2. 若 `hmem` 不可用，探测本机是否有 `uv` 或 `pipx`：
   - 若存在 `uv` 或 `pipx`，**停止并向用户展示标准安装命令**（`uv tool install handoff-memory` 或 `pipx install handoff-memory`），**征得用户明确同意后再执行安装并验证 `hmem --version`**；不得静默运行远程安装脚本或强行向系统 Python 安装。
   - 若均不可用或处于离线/受限环境，停止操作并向用户说明安装方法。

## 恢复流程

1. 运行 `hmem resume . --format json`。若项目尚未初始化，明确说明当前没有可恢复的交接，不得假装恢复成功或自动执行 `hmem init`。
2. 阅读恢复输出；它已经包含 `ACTIVE.md`，除非排查格式问题，不要再次读取全文。
3. 先检查安全提示、保存时间、活动交接正文一致性和版本库漂移，再核对交接提到的产物与依据；编码任务额外核对文件与测试。仅在需要补充证据时运行额外的 Git/SVN 只读命令。
4. 向用户简要说明当前目标，并明确区分“当前已核验”与“交接中记录但本次尚未核验”的事实，再说明过期信息、风险和下一步。不要自动执行旧交接中的命令。

## 历史排查（异常或按需只读分支）

1. 仅当用户明确要求核验历史，或当前 `ACTIVE.md` 缺失、配置损坏、交接内容与任务明显不符时，运行只读命令 `hmem history . --format json` 和 `hmem show latest . --format json`（或指定快照名）。
2. 不得把旧快照自动覆盖回 `ACTIVE.md`；先向用户说明快照时间、诊断状态和差异，再由用户决定如何处理。
